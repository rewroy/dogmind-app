Dogmind は、あなたの Windows PC で動く AI エージェントのネイティブアプリです。選んだフォルダーのファイルを読み書きし、そこでコマンドを実行します。実行の前には確認を求めます。エンジンは別のプログラムの [Straydog](https://github.com/rewroy/Straydog) で、この PC でモデルを動かします。新しい `straydog.exe` をアプリの横に置けば、それがエンジンの更新になります。別のマシンのモデル、オンラインのサービス、Codex、Claude も使えます。

- **軽い。** Win32 のアプリで、画面は Direct2D と DirectWrite で CPU が描き、文章は RichEdit で表示します。描画に GPU のメモリを使わないので、VRAM はモデルのために残ります。WebView2 を使うのはプレビューを開いている間だけです。日本語入力、選択、コピーは Windows の機能をそのまま使います。日本語は、アプリに同梱した BIZ UDゴシックで表示します。PC にフォントをインストールすることはありません。
- **エンジンは横に置くだけ。** `straydog.exe` は使うときだけ子プロセスとして起動し、やり取りはコマンドラインと OpenAI 互換 API だけで行います。ウィンドウのプロセスが GPU のライブラリを読み込むことはありません。
- **ワークスペースごとのセッション。** サイドバーにワークスペースごとのセッションが並びます。新しいセッションは、フォルダーを選んで始めます。
- **どのモデルでも。** 接続先は「設定 > モデルと接続先」で設定します。モデルのチップの「接続先...」や `/providers` からも開けます。

| 種類 | 内容 | キー |
| --- | --- | --- |
| この PC の Straydog | このアプリの横（または PATH 上）の `straydog.exe` | 不要 |
| OpenAI 互換 | 別のマシンの Straydog（`http://192.168.0.100:8080/v1`）や、同じ形の API を持つサービス（`https://.../v1`）。モデル名を指定します | 貼り付け（Credential Manager に保存）または `env:NAME` |
| Codex | 公式の Codex CLI を通した ChatGPT のプラン。CLI は自分でインストールしてください（先に `codex login`） | CLI のもの |
| Claude | Messages API。既定は `claude-opus-5-5` | 貼り付け（Credential Manager に保存）または `env:ANTHROPIC_API_KEY` |

キーが設定ファイルに保存されることはありません。設定ファイルには、キーがどこにあるかだけを書きます。`http://` のサーバーに送るキーは、暗号化されずにネットワークを流れます。

## 使い方

Windows 11 で、管理者権限なしで動きます。`DogmindSetup-VERSION.exe`（たとえば `DogmindSetup-0.1.0.exe`）を実行すると、`%LOCALAPPDATA%\Programs\Dogmind` に入り、スタート メニューと「インストールされているアプリ」に登録されます。最初のページにそのフォルダーが表示され、「変更...」で Windows のフォルダー選択から別のフォルダーを選べます。ほかのものが入っているフォルダーを選ぶと、その中に `Dogmind` フォルダーを作ります。管理者でないと書き込めないフォルダー（`C:\Program Files`）や、設定とセッションを置くフォルダーは、理由を示して断ります。更新は今入っている場所に入れるので、フォルダーは選べません。zip の場合は、zip 全体を自分のフォルダーに展開して `dogmind-app.exe` を起動してください。

この PC でモデルを動かすには、新しいドライバーの入った NVIDIA の GPU と、ドライブに約 76 GB の空きが必要です（ダウンロードが 75 GB、残るのは 70 GB）。GPU がなくても、別のコンピューター、オンラインのサービス、Codex、Claude を使えます。「設定 > この PC のモデル」に、Straydog がこの PC で用意できるモデルが並びます。今の GPU の空きメモリより多くを必要とするモデルも、必要な量を添えて「おすすめしません」と灰色で表示します。試したい人のためです。Qwen3.8 の「高速化データ」は、GPU のメモリにかかわらず下書きモデルを取りに行きます(ダウンロード約 5 GB、残るのは 0.9 GB)。すでに用意したモデルでオンにすると、エンジンを動かしたまま下書きモデルだけを取りに行き、作業が終わったときにエンジンを起動し直して使い始めます。

最初の起動で、モデルへの接続方法と作業するフォルダーを聞かれます。`/setup` でもう一度やり直せます。`/` でコマンド、`@` でワークスペースのファイルを選べます。Enter で送信、Shift+Enter で改行、Esc で中止です。Ctrl+N で新しいセッション、Ctrl+, で設定、Ctrl+Shift+C で最後の回答をコピーします。セッションを右クリックすると、名前の変更と削除ができます。

モデルが作業している間に Enter を押すと、入力した内容は次の手順の前に作業へ入ります。Ctrl+Enter なら、作業が終わったあとに回します。待っているメッセージには、今すぐ作業に入れる、編集する、取り消す、のボタンがあります。メッセージには時刻が付きます。回答の分岐ボタンを押すと、その回答までの会話で新しいセッションを始め、そこから別の進め方を試せます。2 ターン目からは、会話の右端にあなたのメッセージごとの印が並びます。読んでいる位置の印は長く表示され、クリックするとそこへ移動します。

いくつかの手順は、会話の中のカードで出ます。
- 質問: エージェントがあなたに聞くときは、質問と、選択肢ごとのボタン(おすすめには印)と、自分の答えの欄がカードに出ます。答えるまで、セッションは「確認待ち」になります。
- 計画: 計画モード(`/plan`)では、計画を「実行する」「変更...」のボタン付きのカードで出します。実行するまで、何も変えません。
- 変更したファイル: ファイルを変えた回答の下に、変更したファイルを増えた行と減った行とともに並べるカードが出ます。押すとそのファイルの差分を開き、もうひとつのボタンでファイルを開くか、エクスプローラーで表示します。
カードは、セッションを開き直しても残ります。
- `/goal 目標` で、セッションに目標を持たせます。目標は題名の下の細いバーに出て、会話を要約したあとにもモデルへ伝え直します。`/goal clear` で終わります。
- `/trajectory` で、セッションの時間がどこにかかったかを、ターンごとに見られます。
- 変更しないことをはっきり頼んだ依頼(「読むだけ」「何も変えないで」)では、そのターンは読み取りだけになり、何かを断る前に 1 行でそう表示します。「テストは変えずに」のように対象のある言い方は、その対象だけを縛ります。
- 道具が持ち帰ったキーやトークンは、画面では伏せて表示します。モデルにはそのまま渡ります。

右の区画(題名の右のボタン、または `/panel`)には「概要」「ファイル」「ターミナル」があります。
- 「ファイル」は、ワークスペースをフォルダーが先の木で表示します。このセッションで変えたファイルには印が付き、ディスクの変化にも追従します。
- クリックすると、会話の横でファイルをプレビューします(Markdown、HTML、画像、コードとテキスト、表としての CSV と TSV、Excel のブックの最初のシート)。
- ダブルクリックすると、ファイルの既定のアプリで開きます。
- 右クリックで、開く、エクスプローラーで表示する、パスをコピーする、メッセージで触れる(`@パス`)を選べます。

「ターミナル」(`/terminal`、または Ctrl+`` ` ``)は、会話の横で使う、あなた自身のシェルです。
- PowerShell 7、Windows PowerShell、コマンド プロンプト、そして完全な Git for Windows が入っていれば Git Bash を選べます(Dogmind に付いてくる Git には bash がありません)。「新しいターミナル」は最後に選んだシェルを開き、横の矢印で別のシェルを選べます。シェルはセッションのフォルダーで始まります(フォルダーがなければ、あなた自身のフォルダー)。
- Windows ターミナルと同じように動きます(擬似コンソール ConPTY)。16色、256色、フルカラー、太字、下線、カーソル、全角の日本語、git、python、vim、進捗バーも使えます。シェルはあなた自身の環境変数を受け継ぐので、そこに `NO_COLOR`(起動元のツールが設定していることがあります)があれば、シェルにも渡り、それに従うプログラムは色なしで表示します。
- ターミナルは 8 個までのタブで、ダブルクリックで名前を変え、×で閉じます。閉じると、シェルと、それが起動したものすべてが終わります。Dogmind を終了したときも同じです。パネルを畳んでも、別の表示にしても、別のセッションを開いても、動き続けます。終わったシェルは終了コードと「新しいターミナル」のボタンとともに画面に残り、勝手に再起動することはありません。
- キーを受けている間は、Ctrl+`` ` ``(別のターミナル)、Ctrl+Tab と Ctrl+1〜9(セッションの切り替え)、F6(ターミナルから出てメッセージ欄へ)を除いて、すべてのキー(Tab、矢印、F キー、Ctrl や Alt と文字)がシェルに渡ります。Ctrl+C は選択があるときはコピー、ないときはシェルへの ^C です。Ctrl+V、Ctrl+Shift+V、Shift+Insert は貼り付けです(シェルが求めれば貼り付けとして渡します)。ドラッグで選択し(ダブルクリックで単語、トリプルクリックで行)、ホイールと Shift+PgUp で直近 10,000 行までさかのぼれます。右クリックで、コピー、貼り付け、すべて選択を選べます。
- IME の確定した文字はそのまま入り、変換中の窓はカーソルの位置に出ます。色と書体(Cascadia Mono、なければ Consolas)はテーマに従い、スクリーンリーダーには「ターミナル」というドキュメントとして、見えている文字とカーソルのある行が伝わります。
- **ここで行うことは、エージェントではなくあなたのものです。** コマンドはあなた自身の権限で動き、エージェントの権限や制限は及びません。ターミナルに表示されるものは、モデルには送られません。

## 会話の暗号化

会話は `%LOCALAPPDATA%\DogmindApp\sessions` に平文の JSON 行として保存されます。「設定 > プライバシー」でオンにしない限り暗号化されません。既定はオフで、オフならコストはかかりません。

- **暗号化されるもの。** 会話のすべてのメッセージ(1 行ずつ。AES-256-GCM で、行を別のファイルや別の位置へ移すことはできず、1 バイトでも変わった行は破損として報告し、黙って捨てることはしません)、会話の画像(1 枚ずつ丸ごと)、モデルが次のセッションのために残すメモと、忘れたメモ、そしてセッションの元に戻す地点の索引(あなたの依頼の冒頭の言葉を含みます)。暗号化したセッションの先頭には、暗号化していることと、ファイル固有のランダムな ID、鍵の指紋だけを書いた平文の 1 行が残ります。会話の内容は一切含みません。書き込みはこれまでどおり 1 行ずつの追記なので、ディスクへの書き込みは増えません。
- **暗号化されないもの。** ワークスペースのファイルと、編集を元に戻すために残すそのコピー(どちらを選んでも、ワークスペースにはもともとそのまま置かれています)。セッションの横の計測記録(`.trajectory.jsonl`。回数、時間、名前、結果、短いハッシュだけで、話した内容は含みません。ただし、道具が触ったファイルの名前とコマンドの最初の単語、サーバーが失敗について返した 1 行は含みます)。設定。会話の横のパネルで開いた画像と、コマンドが読めるように置く添付画像のコピーは、`attachments` に平文で置かれ、アプリを起動するたびに空になります。
- **オンにするとき。** パスフレーズを 2 回入力すると、回復コードが一度だけ表示されます。「この PC で覚える」は、外さない限りチェックされています。そのあと、今ある会話を 1 件ずつ、進み具合を見せながら暗号化します。各ファイルは古いファイルの横に丸ごと書いてから置き換えるので、クラッシュや停電があっても、どのファイルも古いままか新しくなったかのどちらかで、残りは次の起動で仕上げます。新しい会話は始まるときから暗号化し、平文の会話もそのまま開けます。会話が作業している間は何も変えません。
- **鍵。** ランダムな 256 ビットの鍵で会話を暗号化します。その鍵は、`conversation-key.json` に包んだ形(AES-256-GCM)でしか保存されません。包む鍵は、あなたのパスフレーズから scrypt で作った鍵、回復コード(約 160 ビット)から scrypt で作った鍵、そして「この PC で覚える」にチェックがあれば、あなたの Windows ユーザーの DPAPI の 3 つです。パスフレーズか回復コードのどちらか一方で、この PC でも別の PC でも、Windows を入れ直したあとでも会話を開けます。DPAPI の鍵はこの PC で、あなただけが開け、これがあると起動時に何も聞きません。なければダイアログがパスフレーズ(または回復コード。その場合は新しいパスフレーズ)を聞き、答えるまでは会話を開くことも書くこともしません。
- **変更。** 「設定 > プライバシー」で、パスフレーズの変更(会話には手を加えません)、新しい回復コードの作成(古いコードは使えなくなります)、「この PC で覚える」のオンとオフ、そして暗号化をやめることができます。やめるときは、確認のあとで、すべての会話を平文に戻し、鍵のファイルを削除します。
- **パスフレーズと回復コードの両方を失うと、会話は誰にも、あなたにも読めなくなります。** ほかに入る方法はありません。回復コードは表示されたときに書き留めてください。表示は一度だけで、どこにも保存されません。`conversation-key.json` を含めてアプリのフォルダーをコピーしても、会話は暗号化されたままです。
- **コスト。** この PC で、テスト用の 200 セッション(157 MiB、最大は 24 MiB)のフォルダーを測りました。ロック解除はパスフレーズで 38 ms、この PC 用のコピーで 0.2 ms。最大のセッションを開くのは 42 ms が 60 ms に、1 行の追記は 3 us が 4 us に、全セッションの一覧は 126 ms が 233 ms に、全セッションの検索は 0.4 秒が 0.6 秒になります。ファイルは 3 分の 1 ほど大きくなり(各行の base64 とタグのため)、フォルダー全体を最初に暗号化するのに 2.8 秒かかりました。

## エンジンの次の起動のために会話を残す

エンジンが起動し直すと(アプリの更新や、エンジンの再起動を伴う設定の変更など)、長い会話の次のメッセージで会話全体をもう一度読み込みます。小さなグラフィックスカードでは、36,000 トークンの会話で最初の一語までに 84 秒かかりました。「設定 > プライバシー > 次の起動のために会話の状態を残す」はこれをなくします。**既定はオフ**で、オフならここに書いたことは何も変わりません。

- **残すもの。** エンジンが直前に持っていた会話の、エンジン自身の状態です。最後の返事が始まった場所のもので、会話をもう一度読み込んで得る数値と同じものです(会話の文章ではありません。文章はこれまでどおりアプリが保存します)。画像を含む会話と、1024 トークンに満たない会話は残しません。
- **場所と封のしかた。** エンジンのデータフォルダーの `conversation` に、モデルごとに 1 ファイル(新しいものが古いものを置き換えます)。ランダムな鍵を Windows の DPAPI があなたの Windows アカウントのために包み、その鍵で AES-256-GCM により封をします。エンジンがほかに保存する状態(システムプロンプトの状態)と同じ封です。ほかの Windows ユーザーは開けず、1 バイトでも変わると拒みます。ファイルは会話の 1 トークンあたり約 28 KB で、書き込みを速くするドラフターがあるとやや増えます(36,000 トークンで 1.0 GB)。
- **書くとき。** エンジンが意図して止まるときに 1 回だけ、ほかには書きません。作業中も、メッセージごとにも書かないので、ドライブへの書き込みはアプリを閉じるときの 1 回です。アプリは、アプリだけが持つパイプでエンジンに止まるよう頼み、最大 20 秒、終わるのを待ち、それでも終わらなければこれまでどおり終わらせます。アプリを終了するとき、更新、エンジンの再起動を伴う設定の変更、Windows のサインアウトとシャットダウンが対象です(待つ理由は Windows に伝えます)。ドライブの空きやメモリに収まらない状態は書かず、エンジンのログに 1 行で書きます。
- **次の起動で。** エンジンはその会話の続きになる最初のメッセージのときにだけファイルを読み、ログの行に `reused 36100 from kept, loaded in 3.2 s` と出ます。続きにならないメッセージは、あとのメッセージのためにファイルをそのまま残します。別のビルドのエンジンのファイルと、開けないファイルは削除します。オプションをオフにしたときも、エンジンの起動時にファイルを削除します。
- **会話を暗号化しているとき。** 状態はあなたの Windows アカウントのために封をされ、パスフレーズなしで開けます。そのため、会話を暗号化していて「この PC で覚える」がオフのときは、オプションはオフで、オンにできません(ページに理由を書きます)。その組み合わせにするとオプションはオフになります。「この PC で覚える」にチェックがあれば、会話の鍵も同じように Windows があなたのアカウントのために開けるので、状態が鍵より読みやすくなることはありません。

## 更新、削除、困ったとき

新しい版は [Releases](https://github.com/rewroy/dogmind-app/releases) で公開します。アプリが GitHub に新しいリリース（プレリリースを含む）を問い合わせるのは 6 時間ごとと、前の確認から 1 時間以上たってからウィンドウをトレイから出したときです。「設定 > このアプリについて」に「更新を確認」があり、この確認を止めるスイッチ（「自動で更新する」）もあります。問い合わせに含まれるのはアプリのバージョンだけで、あなたについての情報は送りません。インストーラーが入れたフォルダーから動いているアプリは、新しいリリースのセットアップを、GitHub がサイズと SHA-256 を公開している場合に限り、バックグラウンドでダウンロードします（従量制の接続では、「更新を確認」を押さない限りダウンロードしません）。ダウンロード中のファイルはアプリのデータフォルダーの `updates` に `.partial` として置かれ、サイズとハッシュが GitHub の公開値と一致したときだけ残ります。一致しないとき、またはキャンセルしたときは削除します（進み具合とキャンセルは「設定 > このアプリについて」にあります）。準備ができると、どのページを開いていても、メイン画面の上のカードで知らせ、「今すぐ更新（Dogmind を再起動します）」と「あとで」のボタンを出します（ウィンドウが隠れている間は、新しい版ごとに 1 回トレイから知らせます）。セットアップを実行するのはこのボタンだけで、作業中なら終わってから実行します（`DogmindSetup-VERSION.exe --update --dir フォルダー --wait-pid PID`。何も尋ねず、アプリの終了を待ち、フォルダーを更新し、失敗したら元に戻し、アプリをもう一度起動します）。zip から展開したアプリには、リリースページを開くボタンだけが出ます。

更新するには、新しい `DogmindSetup-VERSION.exe` を実行してください。動いているアプリに閉じるよう依頼し（作業中のアプリは開いたままで、その旨を表示します。強制終了はしません）、各ファイルをハッシュで確かめ、変わったものだけを置き換え、前の版が置いたものだけを取り除きます。ファイルはすべて置き換わるか、ひとつも置き換わらないかのどちらかです。途中で失敗したら元のファイルを戻すので、アプリは前のまま動きます。もう一度実行すれば続きから進みます。zip の場合は、トレイから終了し（ウィンドウを閉じただけでは動き続けます）、新しい zip を元のフォルダーに上書きで展開してください。設定とセッションは `%LOCALAPPDATA%\DogmindApp` にあり、そのまま残ります。

ダウンロードするセットアップは、いつも全体とは限りません。リリースにはセットアップの隣に、各ファイルがセットアップのどこにあるかを示す `DogmindSetup-VERSION.parts` があり、インストーラーは入れた各ファイルのハッシュ、サイズ、最終更新時刻を、インストール先のマニフェストに書き留めます（0.1.5 より前に入れたものには記録がないため、最初の更新は全体をダウンロードし、フォルダーのすべてのファイルを一度読みます）。リリースが `.parts` ファイルもサイズと SHA-256 付きで載せていて、マニフェストにその記録がある場合、アプリはプログラムと、新しいか変わったファイルだけを HTTP の範囲指定でダウンロードし、それ以外のファイルはインストール先に任せるセットアップを `updates` フォルダーに組み立てます。`.parts` ファイルは GitHub が公開したサイズと SHA-256 で確かめ、各部分はその内容で確かめます（プログラムはハッシュで、各ファイルは展開してサイズと SHA-256 を照らして）。インストーラーは、省かれたファイルをフォルダーの中から記録で見つけ（書き留めた時刻と違うファイルはハッシュで）、ひとつでも前のままでなければ何も変えず、リリースページから完全なセットアップをダウンロードするよう伝えます。途中でどこかが期待どおりでなければ、上のとおり全体をダウンロードし、そのことは何も表示しません。インストーラーはこの記録を、アプリ自身の更新（`--update`）でだけ使います。書き留めたサイズと時刻のままのファイルは、読み直しません。自分でセットアップを実行したときはすべてのファイルを調べるので、インストールの修復にはそれを使ってください。

削除するには「設定 > 全般 > この PC からアプリを削除」を使います。設定、セッション、ログ、Credential Manager にあるこのアプリのキー、サンドボックスに開いたもの、このアプリの AppContainer プロファイル、それにモデルを削除します（モデルは残すこともできます）。データフォルダーの中では、このアプリが作ったものだけを名前で選んで削除します。ほかのものは残し、何を残したかを表示します。Straydog のサンドボックスのプロファイルは残します。エンジンは単体のサーバーとしても動くためです。「インストールされているアプリ」から削除すると同じページが開き、それを閉じるとプログラムと登録も削除します。削除するのはインストーラーが置いたファイルだけで、フォルダーは空になったときだけ削除します。zip の場合は、アプリのフォルダーを削除してください。ワークスペースには手を付けません。

アプリが異常終了すると、`%LOCALAPPDATA%\DogmindApp\crashes` にテキストファイルを残し、次の起動時にお知らせします。`/report`、または「このアプリについて > 問題のレポートを作成」で `%LOCALAPPDATA%\DogmindApp` に `report.txt` を作ります。キー、サーバーのアドレス、会話は含みません。ただし、失敗のときにアプリの文の下に出る、エンジンまたはサーバーが言った最後の 1 行は含みます（キーやヘッダーは伏せます）。内容を確認してから、何をしていたかを添えて [Issue](https://github.com/rewroy/dogmind-app/issues) に添付してください。自動で送信されることはありません。リリースを作る人は、そのリリースの `dogmind_app.pdb` と `straydog.pdb` を保管してください。異常終了時のアドレスは、これを使って読み解きます。
セキュリティの問題は、公開の Issue ではなく、[SECURITY.md](SECURITY.md) にある方法で非公開で報告してください。

このアプリにはまだ署名がありません。Windows が「Windows によって PC が保護されました」と表示したら、「詳細情報 > 実行」を押してください。スマート アプリ コントロールが有効な場合、Windows はこのアプリを実行しません。

## ビルド

```bat
set "RUSTFLAGS=-C target-feature=+crt-static --remap-path-prefix=%USERPROFILE%=~"
cargo build --release -p dogmind-app -p dogmind-setup
```

リリースはこの設定でビルドします。パニックのメッセージにはソースのパスが入るので、パスの置き換えがないと、ビルドした人のユーザーフォルダーがすべてのメッセージに入ってしまいます。`RUSTFLAGS` は `.cargo/config.toml` の設定を置き換えるので、C ランタイムの静的リンクをもう一度指定しています。

続けて `python -I scripts\package.py` を実行すると、`dist\DogmindApp`、その zip、`dist\DogmindSetup-VERSION.exe` ができます。インストーラーは `crates/dogmind-setup` だけで、ほかのツールは使いません。パッケージはその実行ファイルの末尾に、ファイルごとに圧縮して付けてあり、先頭から順に読みます。作業用のフォルダーで試すには `DogmindSetup.exe --test --dir FOLDER` を使います。スタート メニューやレジストリには書き込まず、書き込むはずだった内容をそのフォルダーに書き出します。`--test` を付けない `--dir FOLDER` は、最初のページに表示するフォルダーを選ぶだけです。

作業は次の版のブランチ `dev/X.Y.Z` で進め、`main` には公開した版だけを置きます。リリースするには、`dev/X.Y.Z` でワークスペースの `Cargo.toml` の `version` を上げ、上の手順でビルドとパッケージ作成をします。次に `dev/X.Y.Z` を pull request でマージコミットとして `main` に合流させ（squash はしません）、そのマージコミットに `vVERSION`（たとえば `v0.1.0`）というタグでプレリリースを公開し、`dist\DogmindSetup-VERSION.exe`、`dist\DogmindSetup-VERSION.parts`（これがあるときだけ、アプリは更新を部分ごとにダウンロードします。なければ全体）、`dist\DogmindApp-VERSION.zip` を添付します。PDB は手元に保管してください。アプリの更新確認は、タグのバージョンがいちばん新しいリリースをお知らせします。プレリリースも対象で、下書きはお知らせしません。バージョンになっていないタグは無視します。

GPU のツールキットは不要です。エンジンを使うには、Straydog の README の手順でビルドした `straydog.exe` を、ツールキットの `cublas64_13.dll` と `cublasLt64_13.dll` と一緒に、`dogmind-app.exe` の横にコピーしてください。

パッケージには、実行ファイルの横に `tools\` も入っています。使う人が何もインストールしなくても、どのマシンでもコマンドが同じように動くようにするためです。中身は、よく使うモジュール入りの Python、npm と npx 入りの Node.js、Git で、サンドボックスで実行するコマンドの PATH の先頭に、インストール済みのものより先に置きます。`python -I scripts/fetch_tools.py` が、`scripts/tools.lock.json` に固定したハッシュでこのツリーの外のキャッシュに取得し、`python -I scripts/package.py` がそれらをまとめてライセンスを加えます。横に `tools\` のない開発ビルドは、マシンにあるもの、または `DOGMIND_TOOLS` で指定したフォルダーを使います。

## エージェント

ツールで、ファイルの読み取り、検索、作成、編集（`read_file`、`list_files`、`find_files`、`search_files`、`create_file`、`apply_patch`）、コマンドの実行（`execute_command`）、変更内容の表示（`show_diff`）、ToDo リストの管理、ブラウザでの Web ページの確認ができます。設定で有効にすれば、Web の検索と読み取りもできます。編集とコマンドは、モード（*既定*、*編集を許可*、*自動*）に従って先に確認を求め、そのたびに Paw Note を示します。Paw Note は、承認の前に示す説明のことです。会話に Web の内容（検索、読み取った Web ページ、信頼していない MCP サーバーの返答）が入ったあとは、そこから求められたかもしれないことを、モードや保存した規則にかかわらず毎回確認します。ネットワークを使うコマンド、MCP のツール、メモの保存と削除、あなたも Web も示していないアドレスの読み取りです。ネットワークを使わないコマンドは、それまでと同じに扱います。長いセッションは 3 段階で圧縮し、セッションはそれぞれ 1 つのファイルに保存します。プロジェクトの `DOGMIND.md`（または `AGENTS.md`、`CLAUDE.md`）に、そのプロジェクトでの作業の仕方を書けます。モデルが読む文章は、ローカルのモデルに必要なだけに絞っています。システムプロンプトは `crates/dogmind-agent/src/prompt.rs`、ツールの定義は `tools.rs` にあります。

選択肢つきであなたに質問すること(`ask_user`)もでき、計画モードでは計画を承認に出し(`submit_plan`)、承認されたら実行します。

長い調べもののときは、`explore` が質問を、専用のコンテキストと調べる道具だけを持つヘルパーに渡し、その答えだけを会話に加えます。800 行を超えるファイルを位置を指定せずに読むと、まず概要を返します。ファイルを 96 KB 読むごとにそのターンへお知らせします。長い道具の結果(コマンドの出力、検索、編集の報告、差分、MCP の道具の答え)は `%TEMP%\dogmind-output` に丸ごと 1 週間残し、続きを読む場所を伝えます。圧縮で古い出力から刈り込んだ分も同じように残します。バックグラウンドで動かしたままのコマンドは、`command_status` のたびに、前回から出力された分を見せます。開発サーバーの起動完了の行もそこに出ます。

`execute_command` は、`DogmindApp.Exec` という AppContainer の中で動きます。コマンドが書き込めるのはワークスペースだけで、読めるのはワークスペース、PATH 上のユーザーごとのツールチェーン、どのアプリでも読めるものです。ネットワークは、承認されたときだけ、その都度使えます。コマンドが起動したものは、コマンドと一緒に終わります。閉じ込められないものは実行しません。代わりの実行方法はありません。ドライブ全体や、ユーザーフォルダーを含むワークスペースでは、コマンドはいっさい実行できません（読み取りと編集はでき、開始時にその旨を表示します）。

AppContainer は ACE で動くので、ワークスペースで最初にコマンドを実行したとき、そのフォルダーとその下、ツールチェーンのフォルダーに ACE を書き込みます。これは残ります。取り除くには `icacls <フォルダー> /remove <プロファイルの SID> /t` を実行してください。アプリ自身のファイル操作はコンテナの外で動き、代わりに承認を通ります。

## バックグラウンドの作業

`background: true` で始めたコマンドは、エージェントが別のことをしている間も、あるいはターンを終えても動き続けます。コマンドが終わると、どんな終わり方でも、セッションは自分で動き出します。アプリが通知を書き、会話では専用の行として表示し、モデルはそれをあなたの言葉ではなくアプリからの連絡として読みます（通知に入るコマンドの出力はデータで、指示としては扱いません）。誰も何も送らないまま、1 ターンが実行されます。`wake_on`（正規表現）を指定すると、コマンドが最初に出力した一致する行（サーバーなら `Listening on`）で 1 回だけ動き出し、コマンドはそのまま続きます。`wake_at` は、60 秒から 1 日までの時間とメモを指定してあとで動き出させます。同時に開けるのは 5 つまでです。`command_stop` はコマンドを止めるか待機を取り消し、そのときは動き出しません。ターンの途中で届いた通知はターンの終わりまで待ち、同時に届いた通知は 1 ターンにまとめます。

暴走しないように、あなたの言葉なしに続けて動き出すのは 30 回まで、1 時間では 60 回までです。どちらかを超えると止まり、理由を画面に表示します（前者はあなたがメッセージを書くと、後者は 1 時間たつと続きます）。あなたの Stop は、そのターンと、そのセッションのコマンドと待機をすべて止めます。動き出したターンも、ほかのターンと同じく確認を求めて待ちます。見るまでタスクバーのボタンが点滅し、ウィンドウが隠れているときはトレイがそのことを知らせます。何かが代わりに承認することはありません。右のパネルに待っているものを一覧し、それぞれに止めるボタンがあります。セッション一覧では、待っているものがあるセッションに印が付きます。ウィンドウを閉じても、すべてトレイで動き続けます。トレイの終了で、すべて終わります。コマンドと待機はアプリより長くは残らず、ファイルの監視や、アプリの外からの合図の受け付けはしません。

## Straydog

このアプリは Straydog とコードを共有していません。Straydog は独自に進んでいきます。アプリは `straydog.exe` を起動し、`straydog setup` を実行し、`fetch --help` からバンドルを読み、HTTP でやり取りします。そのすべてが `crates/dogmind-app/src/engine.rs` にあるので、Straydog の変化を追いかける作業は、ほとんど読むだけで済みます。
