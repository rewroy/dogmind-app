# Dogmind

[English](README.md)

Dogmind を Windows のネイティブアプリにしたものです。サーバーとして使うなら `straydog`、ターミナルで使うなら `dogmind` を、ウィンドウで使うならこのアプリを動かします。このアプリは独立した製品で、Straydog をプログラムとして使います。新しい `straydog.exe` を横に置けば、それがエンジンの更新になります。

- **軽い。** Win32 のアプリで、画面は Direct2D と DirectWrite で CPU が描き、文章は RichEdit で表示します。描画に GPU のメモリを使わないので、VRAM はモデルのために残ります。WebView2 を使うのはプレビューを開いている間だけです。日本語入力、選択、コピーは Windows の機能をそのまま使います。日本語は、アプリに同梱した BIZ UDゴシックで表示します。PC にフォントをインストールすることはありません。
- **エンジンは横に置くだけ。** `straydog.exe` は使うときだけ子プロセスとして起動し、やり取りはコマンドラインと OpenAI 互換 API だけで行います。ウィンドウのプロセスが GPU のライブラリを読み込むことはありません。
- **ワークスペースごとのセッション。** サイドバーにワークスペースごとのセッションが並びます。新しいセッションは、フォルダを選んで始めます。
- **どのモデルでも。** 接続先は「設定 > モデルと接続先」で設定します。モデルのチップの「接続先...」や `/providers` からも開けます。

| 種類 | 内容 | キー |
| --- | --- | --- |
| この PC の Straydog | このアプリの横（または PATH 上）の `straydog.exe` | 不要 |
| OpenAI 互換 | 別のマシンの Straydog（`http://192.168.0.100:8080/v1`）や、同じ形の API を持つサービス（`https://.../v1`）。モデル名を指定します | 貼り付け（Credential Manager に保存）または `env:NAME` |
| Codex | 公式の Codex CLI を通した ChatGPT のプラン。CLI は自分でインストールしてください（先に `codex login`） | CLI のもの |
| Claude | Messages API。既定は `claude-opus-5-5` | 貼り付け（Credential Manager に保存）または `env:ANTHROPIC_API_KEY` |

キーが設定ファイルに保存されることはありません。設定ファイルには、キーがどこにあるかだけを書きます。`http://` のサーバーに送るキーは、暗号化されずにネットワークを流れます。

## 使い方

Windows 11 で、管理者権限なしで動きます。`DogmindSetup-VERSION.exe`（たとえば `DogmindSetup-0.1.0.exe`）を実行すると、`%LOCALAPPDATA%\Programs\Dogmind` に入り、スタート メニューと「インストールされているアプリ」に登録されます。最初のページにそのフォルダが表示され、「変更...」で Windows のフォルダ選択から別のフォルダを選べます。ほかのものが入っているフォルダを選ぶと、その中に `Dogmind` フォルダを作ります。管理者でないと書き込めないフォルダ（`C:\Program Files`）や、設定とセッションを置くフォルダは、理由を示して断ります。更新は今入っている場所に入れるので、フォルダは選べません。zip の場合は、zip 全体を自分のフォルダに展開して `dogmind-app.exe` を起動してください。

この PC でモデルを動かすには、新しいドライバーの入った NVIDIA の GPU と、ドライブに約 76 GB の空きが必要です（ダウンロードが 75 GB、残るのは 70 GB）。GPU がなくても、別のコンピューター、オンラインのサービス、Codex、Claude を使えます。「設定 > この PC のモデル」に、Straydog がこの PC で用意できるモデルが並びます。今の GPU の空きメモリより多くを必要とするモデルも、必要な量を添えて「おすすめしません」と灰色で表示します。試したい人のためです。

最初の起動で、モデルへの接続方法と作業するフォルダを聞かれます。`/setup` でもう一度やり直せます。`/` でコマンド、`@` でワークスペースのファイルを選べます。Enter で送信、Shift+Enter で改行、Esc で中止です。Ctrl+N で新しいセッション、Ctrl+, で設定、Ctrl+Shift+C で最後の回答をコピーします。セッションを右クリックすると、名前の変更と削除ができます。

モデルが作業している間に Enter を押すと、入力した内容は次の手順の前に作業へ入ります。Ctrl+Enter なら、作業が終わったあとに回します。待っているメッセージには、今すぐ作業に入れる、編集する、取り消す、のボタンがあります。メッセージには時刻が付きます。回答の分岐ボタンを押すと、その回答までの会話で新しいセッションを始め、そこから別の進め方を試せます。2 ターン目からは、会話の右端にあなたのメッセージごとの印が並びます。読んでいる位置の印は長く表示され、クリックするとそこへ移動します。

## 更新、削除、困ったとき

新しい版は [Releases](https://github.com/rewroy/dogmind-app/releases) で公開します。アプリが GitHub に最新のリリースを問い合わせるのは 1 日に 1 回までで、新しい版があれば控えめにお知らせし、そのページを開くボタンを出します。自分でダウンロードやインストールをすることはありません。「設定 > このアプリについて」に「更新を確認」があり、毎日の確認を止めるスイッチもあります。問い合わせに含まれるのはアプリのバージョンだけで、あなたについての情報は送りません。

更新するには、新しい `DogmindSetup-VERSION.exe` を実行してください。動いているアプリに閉じるよう依頼し（作業中のアプリは開いたままで、その旨を表示します。強制終了はしません）、各ファイルをハッシュで確かめ、変わったものだけを置き換え、前の版が置いたものだけを取り除きます。ファイルはすべて置き換わるか、ひとつも置き換わらないかのどちらかです。途中で失敗したら元のファイルを戻すので、アプリは前のまま動きます。もう一度実行すれば続きから進みます。zip の場合は、トレイから終了し（ウィンドウを閉じただけでは動き続けます）、新しい zip を元のフォルダに上書きで展開してください。設定とセッションは `%LOCALAPPDATA%\DogmindApp` にあり、そのまま残ります。

削除するには「設定 > 全般 > この PC からアプリを削除」を使います。設定、セッション、ログ、Credential Manager にあるこのアプリのキー、サンドボックスに開いたもの、このアプリの AppContainer プロファイル、それにモデルを削除します（モデルは残すこともできます）。データフォルダの中では、このアプリが作ったものだけを名前で選んで削除します。ほかのものは残し、何を残したかを表示します。Straydog のサンドボックスのプロファイルは残します。エンジンは単体のサーバーとしても動くためです。「インストールされているアプリ」から削除すると同じページが開き、それを閉じるとプログラムと登録も削除します。削除するのはインストーラーが置いたファイルだけで、フォルダは空になったときだけ削除します。zip の場合は、アプリのフォルダを削除してください。ワークスペースには手を付けません。

アプリが異常終了すると、`%LOCALAPPDATA%\DogmindApp\crashes` にテキストファイルを残し、次の起動時にお知らせします。`/report`、または「このアプリについて > 問題のレポートを作成」で `%LOCALAPPDATA%\DogmindApp` に `report.txt` を作ります。キー、サーバーのアドレス、会話は含みません。内容を確認してから、何をしていたかを添えて [Issue](https://github.com/rewroy/dogmind-app/issues) に添付してください。自動で送信されることはありません。リリースを作る人は、そのリリースの `dogmind_app.pdb` と `straydog.pdb` を保管してください。異常終了時のアドレスは、これを使って読み解きます。
セキュリティの問題は、公開の Issue ではなく、[SECURITY.md](SECURITY.md) にある方法で非公開で報告してください。

このアプリにはまだ署名がありません。Windows が「Windows によって PC が保護されました」と表示したら、「詳細情報 > 実行」を押してください。スマート アプリ コントロールが有効な場合、Windows はこのアプリを実行しません。

## ライセンス

アイコンは `assets/app.ico` で、`scripts/make_icon.py` が元の絵 `assets/app.png` から作ります。

このリポジトリは MIT ライセンスです（`LICENSE`）。このアプリが追いかけているエージェント Dogmind から取り入れたものは、Dogmind の Apache-2.0 のままです（`assets/licenses/dogmind-LICENSE.txt`）。対象は、Dogmind の文面そのままの `assets/dogmind/` と、Dogmind のものを元にここで手を加えたシステムプロンプト、ツールの定義、エージェントのループです（下の「Dogmind から取り入れたもの」を参照）。`assets/lucide/` のアイコンは Lucide のものです（ISC、`assets/lucide/LICENSE`）。

`scripts/package.py` は、実行ファイルの横に `LICENSE.txt` をひとつ置きます。中身は Dogmind（Apache-2.0）、Straydog（MIT）、Lucide（ISC）、BIZ UDゴシック（SIL OFL 1.1）、CUDA ツールキット、WebView2 SDK、同梱のツール、それにアプリと `straydog.exe` に含まれるすべての Rust クレートのライセンス文です。ここか Straydog の依存関係が変わったら、`python scripts/licenses.py` を実行してください。

## ビルド

```bat
set "RUSTFLAGS=-C target-feature=+crt-static --remap-path-prefix=%USERPROFILE%=~"
cargo build --release -p dogmind-app -p dogmind-setup
```

リリースはこの設定でビルドします。パニックのメッセージにはソースのパスが入るので、パスの置き換えがないと、ビルドした人のユーザーフォルダがすべてのメッセージに入ってしまいます。`RUSTFLAGS` は `.cargo/config.toml` の設定を置き換えるので、C ランタイムの静的リンクをもう一度指定しています。

続けて `python -I scripts\package.py` を実行すると、`dist\DogmindApp`、その zip、`dist\DogmindSetup-VERSION.exe` ができます。インストーラーは `crates/dogmind-setup` だけで、ほかのツールは使いません。パッケージはその実行ファイルの末尾に、ファイルごとに圧縮して付けてあり、先頭から順に読みます。作業用のフォルダで試すには `DogmindSetup.exe --test --dir FOLDER` を使います。スタート メニューやレジストリには書き込まず、書き込むはずだった内容をそのフォルダに書き出します。`--test` を付けない `--dir FOLDER` は、最初のページに表示するフォルダを選ぶだけです。

リリースするには、ワークスペースの `Cargo.toml` の `version` を上げ、上の手順でビルドとパッケージ作成をしてから、GitHub に `vVERSION`（たとえば `v0.1.0`）というタグでリリースを公開し、`dist\DogmindSetup-VERSION.exe` と `dist\DogmindApp-VERSION.zip` を添付します。PDB は手元に保管してください。アプリの更新確認は、公開済みの最新リリースを見ます。下書きとプレリリースはお知らせしません。

GPU のツールキットは不要です。エンジンを使うには、Straydog の README の手順でビルドした `straydog.exe` を、ツールキットの `cublas64_13.dll` と `cublasLt64_13.dll` と一緒に、`dogmind-app.exe` の横にコピーしてください。

パッケージには、実行ファイルの横に `tools\` も入っています。使う人が何もインストールしなくても、どのマシンでもコマンドが同じように動くようにするためです。中身は、よく使うモジュール入りの Python、npm と npx 入りの Node.js、Git で、サンドボックスで実行するコマンドの PATH の先頭に、インストール済みのものより先に置きます。`python -I scripts/fetch_tools.py` が、`scripts/tools.lock.json` に固定したハッシュでこのツリーの外のキャッシュに取得し、`python -I scripts/package.py` がそれらをまとめてライセンスを加えます。横に `tools\` のない開発ビルドは、マシンにあるもの、または `DOGMIND_TOOLS` で指定したフォルダを使います。

## Dogmind から取り入れたもの、取り入れていないもの

エージェントのループ、その終了条件と再試行、システムプロンプト、`read_file`、`list_files`、`search_files`、`apply_patch`、`create_file`、`execute_command`、`show_diff`、`todo`、承認のしくみ（*既定*、*編集を許可*、*自動*、Paw Note）、3 段階の圧縮、セッション（ファイルの形式はこのアプリ独自）、`DOGMIND.md`。

まだないもの: Toybox、プラグイン、汎用のサブエージェント、Dog Nose Work。

このアプリ独自の、長い調べものの扱い（Deepseek Harness が会話の外で調べるのと同じ考え方です）: `explore` は、質問を専用のコンテキストと調べる道具だけを持つヘルパーに渡し、その答えだけを会話に加えます。800 行を超えるファイルを位置を指定せずに読むと、まず概要を返します。ファイルを 96 KB 読むごとにそのターンへお知らせします。長いコマンドの出力や検索結果は `%TEMP%\dogmind-output` に丸ごと 1 週間残し、その場所を伝えます。バックグラウンドで動かしたままのコマンドは、`command_status` のたびに、前回から出力された分を見せます。開発サーバーの起動完了の行もそこに出ます。

`execute_command` は、Dogmind と同じく `DogmindApp.Exec` という AppContainer の中で動きます。コマンドが書き込めるのはワークスペースだけで、読めるのはワークスペース、PATH 上のユーザーごとのツールチェーン、どのアプリでも読めるものです。ネットワークは、承認されたときだけ、その都度使えます。コマンドが起動したものは、コマンドと一緒に終わります。閉じ込められないものは実行しません。代わりの実行方法はありません。ドライブ全体や、ユーザーフォルダを含むワークスペースでは、コマンドはいっさい実行できません（読み取りと編集はでき、開始時にその旨を表示します）。

AppContainer は ACE で動くので、ワークスペースで最初にコマンドを実行したとき、そのフォルダとその下、ツールチェーンのフォルダに ACE を書き込みます。これは残ります。取り除くには `icacls <フォルダ> /remove <プロファイルの SID> /t` を実行してください。アプリ自身のファイル操作はコンテナの外で動き、代わりに承認を通ります。

## 2 つのプロジェクトを追いかける

どちらも独自に進んでいきます。追いかける作業がほとんど読むだけで済むよう、距離を置いています。

- このアプリは Straydog とコードを共有していません。`straydog.exe` を起動し、`straydog setup` を実行し、`fetch --help` からバンドルを読み、HTTP でやり取りします。そのすべてが `crates/dogmind-app/src/engine.rs` にあります。
- モデルが読む文章はこのアプリ独自のもので、ローカルのモデルに必要なだけに絞っています。システムプロンプトは `crates/dogmind-agent/src/prompt.rs`、ツールの定義は `tools.rs` にあります。どちらも元は Dogmind のもので、今もそのまま使っているのは、圧縮のときのプロンプトと Codex のポリシーだけです。`scripts/sync_dogmind.py` が、今の Dogmind の文面を `assets/dogmind` に生成します。`--check` で変化があったかがわかります。変化は読んでから、トークンに見合うものだけを手で取り入れます。
- `UPSTREAM.toml` に、どのコミットまで追いかけたかを書いています。`python scripts/upstream.py` で、それ以降に重要なファイルで何が変わったかを一覧でき、取り入れたあとに `--mark` で記録を進めます。

```bat
python scripts\upstream.py
..\Dogmind\.venv\Scripts\python.exe scripts\sync_dogmind.py
cargo test
python scripts\upstream.py --mark
```

用語は Dogmind の `AGENTS.md` に合わせています。Paw Note は、承認の前に示す説明のことです。
